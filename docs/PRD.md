# 产品需求（PRD）v0

状态：**P0 冻结**。后续改意图枚举、能答/必拒清单或 SSE 事件形状，必须先改本文和 [CONTRACTS.md](CONTRACTS.md)，再改代码。

## 1. 一句话定位

面向大众的**就医导诊与医学科普**助手：先检索公开医疗知识图谱与文档，再生成可溯源、受规则约束的回答。  
**不是医生，不做诊断，不开药，不调剂量。**

## 2. 目标用户与场景

- 用户：有症状、想知道挂哪科、就诊前准备什么、想看疾病/检查/药品的说明书级介绍。
- 非目标：急诊抢救指挥、互联网诊疗、处方流转、个人检查单诊断、慢病远程调药。

对外展示须标明：知识来自公开图谱（OpenKG / 东南大学），**非某家医院号源**。

## 3. 能答清单（In Scope）

| 意图 ID | 名称 | 用户在问什么 | 系统怎么答 |
|---|---|---|---|
| `triage` | 导诊 | 这些症状挂哪科 | 建议科室（可并列），附依据；不说「你得了 XX」 |
| `visit_prep` | 就诊准备 | 去医院带什么、问诊前记什么 | 材料、记录项、注意事项 |
| `knowledge` | 医学科普 | 某病/检查是什么 | 说明书级介绍，带来源 |
| `medication_info` | 药品说明 | 药是什么、常见注意事项 | Cypher 查药名 + 向量查说明；**不给剂量/开药** |
| `emergency` | 急诊识别 | 红旗症状或自伤 | **规则拦截**，引导急救/急诊，不再生成诊疗建议 |
| `chitchat` | 闲聊 | 你好、你是谁 | 固定自我介绍 + 能力边界 |
| `refuse` | 拒答 | 确诊、开药、改剂量、读检查单当诊断 | 明确拒绝，建议线下执业医师 |

开药 / 调剂量 / 停药仍归 `refuse`，不走 `medication_info`。

## 4. 必拒清单（Out of Scope）

系统不得提供：

1. 诊断结论（「你就是偏头痛 / 确诊胃癌」）。
2. 处方或购药建议（「给你开阿莫西林」）。
3. 具体剂量、加量、停药、换药方案。
4. 把用户上传的化验单/影像当诊断来解读。
5. 急救操作步骤（除「立刻打急救电话 / 去急诊」以外的指挥）。
6. 替代执业医师或承诺疗效。

检索命中药品节点时，只允许复述图谱中的通用信息，并强制「遵医嘱或药师指导」。

## 5. 成功标准（P0 可测）

- 急诊金标：**100%** 走 `emergency`，且不进入融合生成。
- 意图分类（金标 v0）：≥ **90%**（`emergency` 不计入此项，单独 100%）。
- 医疗类回答（`triage` / `visit_prep` / `knowledge`）：**100%** 带免责声明。
- 导诊类：给出科室或诚实说「依据不足，建议线下分诊」，禁止空口科室。
- 事实句：上线后须能追溯到检索 `source_id`（板块二强制检索落地后生效）。

评测集：[eval/gold_v0.json](../eval/gold_v0.json)。字段与校验见 [CONTRACTS.md](CONTRACTS.md)。

## 6. 非功能约束

- 主问答：云端模型（默认 DashScope `qwen-plus`），由 `.env` 切换，代码零改动。
- 图谱：只读。禁止模型直接执行写 Cypher。
- 数据：P0–板块一只用 OpenKG 家庭常见疾病图谱 + 手写 FAQ；不爬未授权站点、不入库病历。
- 署名：CC BY-SA 4.0，见 [DATA_ATTRIBUTION.md](DATA_ATTRIBUTION.md)。

## 7. 交互与信息架构（前端未做前先冻结）

- 对话页 + 历史侧边栏 + 来源可点开。
- 每条助手消息至少包含：正文、意图、建议科室或拒答标记、来源列表、安全声明、耗时。
- 顶栏固定黄条：本系统不能替代专业诊疗。

## 8. 明确不在 P0 做的事

在线推理、Neo4j 导入、Vue、微调。P0 只冻结契约与金标。
